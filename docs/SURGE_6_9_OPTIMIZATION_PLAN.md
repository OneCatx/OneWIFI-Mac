# Proletarius — Surge for Mac 6.9.0 设计与架构优化方案

> 记录日期：2026-08-30  
> 原则：保留 Proletarius 全部现有功能与品牌，只借鉴专业网络工具的信息架构、状态反馈、交互密度和渐进披露，不复制第三方品牌、图标或视觉资产。

## 目标

Proletarius 当前功能已经完整，但首页、全局状态仓库和后端入口承担了过多职责。优化目标是把“观察、启停、管理、配置、诊断”分离，同时降低设备并发、轮询竞争、旧状态回写和页面维护成本。

## 信息架构

建议导航结构：

1. 活动
   - 当前设备
   - VoWiFi / IMS 会话
   - 当前通话与短信
   - 实时流量
   - 最近异常
2. 概览
   - DJI 模块总状态
   - 读卡器总状态
   - VoWiFi 状态
   - 隐私遮罩与关键总开关
3. 通信
   - 短信
   - 通话
4. 设备与 SIM
   - 设备
   - eSIM
5. Wi-Fi Calling
   - ePDG 与 IMS 状态
   - 运营商模板
6. 诊断
   - 事件
   - 运行诊断
7. 更多
   - 设置
   - 关于 Proletarius

“活动”只负责观察，“概览”负责启停，“设备与 SIM”负责管理，“网络”负责配置，“诊断”负责查错。

## Surge 交互模式与项目映射

| 专业工具模式 | Proletarius 落地方式 |
|---|---|
| 活动页统一展示网络、流量、连接和异常 | 集中展示设备、IMS、VoWiFi、短信、通话、流量与告警 |
| 概览只放核心状态和总开关 | 首页移除读卡器、eSIM 和诊断细节，只保留能力卡片 |
| 策略使用自适应卡片 | 展示代理出口、ePDG 路径、VoWiFi 会话及健康状态 |
| 规则使用高密度表格 | 展示运营商模板、设备绑定与 Profile 状态 |
| 进程页使用列表—详情双栏 | 用于 DJI 模块、读卡器和 eSIM Profile 管理 |
| 高成本诊断具有时间、容量和数量上限 | 日志和网络诊断采用有边界会话，避免长期影响性能 |
| 高级设置归入“更多” | 外观、更新、日志导出和关于不占主要工作区 |

## 视觉规范

- 使用 macOS 系统字体、语义色和原生控件。
- 侧边栏宽度建议为 200–220 点，页面边距 20 点，区块间距 16 点，控件间距 8 点。
- 卡片圆角保持 10–12 点，避免过强阴影、固定渐变和不必要的玻璃层叠。
- 页面标题使用 `title2`，区块标题使用 `headline`，正文使用 `body`/`callout`，状态说明使用 `caption`。
- 流量、时长和计数使用等宽数字。
- 绿色表示成功，蓝色表示进行中，橙色表示等待或受限，红色表示阻断性失败，灰色表示未连接；状态必须同时包含文字，不能只靠颜色。
- 列表或表格能够表达的高密度信息不再全部包装成卡片。

## 活动页面

- 顶部状态条：DJI、读卡器、IMS、代理和隐私状态。
- 主区域：设备与通信活动、实时上下行、VoWiFi 路径和当前通话。
- 底部：最近短信、最近通话和最近异常。
- 异常可以直接跳转至对应设备或配置位置。
- 隐私遮罩默认开启；活动统计只显示聚合数据，敏感字段按需临时显示。

## 代码架构

### 状态层拆分

将 `DashboardStore` 拆分为：

- `DeviceInventoryStore`
- `DJIModuleStore`
- `ReaderStore`
- `VoWiFiStore`
- `CallStore`
- `TrafficStore`
- `AppCoordinator`

`AppCoordinator` 只负责跨设备协调，不直接执行读卡、通话或 IMS 请求。

### 事件驱动

由后端主动发布设备接入/移除、Profile 切换、IMS 状态、短信、通话、网络出口和错误事件。前端以事件更新为主，保留 15–30 秒低频校准轮询作为兜底，替换当前密集的两秒轮询。

### 设备状态机

统一生命周期：

```text
disconnected → detecting → preparing → ready → active
                              ↓
                            failed
```

每次设备重连或 Profile 切换生成新的 generation；旧请求完成时若 generation 不一致则丢弃，防止旧号码、旧运营商和旧 IMS 状态回写页面。

### 后端拆分

将后端入口按职责拆成 `server.go`、`device_api.go`、`reader_api.go`、`sms_api.go`、`call_api.go`、`call_log.go`、`network_api.go` 和 `diagnostics_api.go`。硬件访问、业务状态、HTTP 接口及持久化相互隔离。

### 错误与持久化

- 错误响应包含稳定错误码、原因、是否可重试、恢复动作、设备和操作 ID。
- 短信、通话记录和设备偏好使用带版本迁移的存储格式。
- 写入采用临时文件、同步与原子替换；损坏数据保留备份。
- 诊断日志默认脱敏，支持会话上限和导出。

## 网络与 VoWiFi 约束

- 不主动绕过前置代理解析 ePDG。
- 不把 Fake-IP 当作异常地址。
- 不自动尝试直连 DNS。
- 故障时不静默回落到系统直连。
- 只展示实际观察到的流量路径。
- `198.18.0.0/15` 标记为由上游透明代理接管，不进行二次解析或重封装。

活动页建议展示只读链路：

```text
读卡器 → IKE / IMS → Fake-IP / 代理接管 → 代理出口 → ePDG
```

## 实施顺序

## 0.09 已落地内容

- 新增默认“活动”页，聚合设备、IMS、通信、流量和当前异常。
- 原“首页”收敛为“概览”，导航分成状态、通信、连接、工具和 Proletarius。
- 导航快捷键重新排序，`Command-1` 直达活动页。
- 通话页显示早期媒体、本地回铃、麦克风与扬声器实际路由。
- 关键失败在活动页以可复制的事实文本呈现，不仅依赖颜色。

后续版本继续按原定阶段拆分 `DashboardStore` 和后端入口；0.09 没有在通话修复中同时进行高风险的全量状态层重写。

### 0.10 活动页校正

- 按 Surge 6.9 的“顶部状态摘要 + 可扫读指标卡”重排活动页。
- DJI 模块、PC/SC 读卡器、IMS 和后台服务状态独立计算，不再用缺失数据推断设备在线。
- 流量卡明确标注为“DJI 模块网络”，不再将单网卡样本冒充为全局流量。
- 读卡器运营商、ePDG、隧道、IMS 和媒体状态分行展示；缺失值只显示“未连接”或 `-`。
- 内容卡圆角、侧边栏宽度和导航密度统一到 Surge 式 macOS 工具层级，但保留 Proletarius 品牌和系统语义色。

### 第一阶段：底层稳定

- 拆分 DashboardStore。
- 增加设备状态机和 generation。
- 统一错误模型。
- 建立后端事件推送。
- 拆分后端入口。

### 第二阶段：信息架构

- 新增活动页。
- 精简概览页。
- 建立统一设备页。
- 将读卡器和 eSIM 细节移出首页。
- 高级设置迁移至“更多”。

### 第三阶段：页面重构

- 重构短信、通话、eSIM 和分流页面。
- 列表型数据改用表格或主从布局。
- 统一空状态、加载状态、错误状态和恢复动作。
- 增加实时活动及路径展示。

### 第四阶段：验证与打磨

- 诊断会话和脱敏导出。
- 硬件并发与性能测试。
- 键盘、VoiceOver、减少动态效果和高对比度适配。
- macOS 26 界面与交互回归。
- 两版 DMG 的安装、升级和签名验证。
