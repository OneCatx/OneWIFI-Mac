# Proletarius 2.63 界面与稳定性优化验收

本轮落实已批准的读卡器布局、页面按钮配色、状态栏呈现和最小稳定性修复。源码在原项目就地更新，保留完整传真及现有 Swift、Rust、Go 架构。没有改动顶部工具栏图标、代理策略、NAS 配置或已由用户确认正常的 9eSIM 切卡协议。

## 基线和采用门槛

基线为 2.62/build262 的完整工作区快照 `build/optimization/2026-09-30-262-final/source.tar.gz`，归档 SHA256 为 `a63de589d7446ce4f62e5d07ec95308e668c6b5db31d25022d8f71da63607f6c`。本轮开始已确认源码与快照一致；没有把仓库旧 HEAD 当作当前用户代码。

确定性缺陷必须在原生产 Store 上复现，并有修复前失败、修复后通过的回归证据。视觉方案需要同尺寸、同数据对照，减少重复信息或滚动，并保留操作入口与错误详情。没有可归因收益的性能重构停止，不用源码行数或包体变化冒充运行速度提升。普通性能改造仍遵循此前已记录的 CPU、p95、构建耗时和两倍成本覆盖门槛，本轮没有新增符合条件的此类候选。

## 修复和取舍

| 范围 | 已采用的最小改动 | 保留边界 |
| --- | --- | --- |
| 切卡时页面重载 | 同一已连接读卡器等待新身份时保留 eSIM 能力和 Profile 布局；清空旧号码、运营商和旧 VoWiFi 状态 | 明确拔卡、换读卡器、实体 SIM 或断开仍清理；不把保留布局解释为旧卡在线 |
| 迟到刷新覆盖新操作 | 新 Profile 操作取消旧刷新、轮询和通知任务；终态延迟刷新校验会话与操作 ID | 不重发写卡、不改变 APDU 或 refresh 参数 |
| 当前卡展示 | Profile 的 ICCID 必须与实时 SIM 身份匹配才能显示已启用 | 缓存 enabled 只能标待确认；未确认身份不能开启新 VoWiFi，但仍能停止 |
| 读卡器布局 | 合并重复标题与连接区域；双栏组织当前卡/Profile 与通信；增加名称筛选、已启用筛选、脱敏诊断复制 | 下载、通知、BLE、切卡、重命名、删除、配置和五阶段全部保留 |
| 状态栏 | 缩小计数占位，去胶囊；模块、读卡器、消息、通话、📠 分组 | 传真只发布内存快照；无新网络、计时器、钥匙串或后台连接 |
| 页面稳定 | 活动页移除每次状态更新强制重建；短信/关于页布局切换保留子视图身份；调试页阻止忙碌时重复回车 | 不改变发送、删除、选择、业务 API 或确认规则 |
| 样式清理 | 收敛蓝色按钮、卡片圆角和间距；删除重复 readerConnectedSection 及零调用 WaterfallLayout | 只影响 opt-in 页面样式，保留顶部图标、品牌资源和传真 emoji；不宣称显著包体收益 |

第一版读卡器重排增加了高度，未通过收益判断，已撤回该布局。最终版压缩重复连接/标题信息，保留待确认身份的固定位置。后者比旧版直接消失占用更多高度，这是避免页面跳变和旧卡信息误导的明确取舍。

## 测量结果

使用真实 ReaderCardView、HomeView 的 reader 内容结构和生产素材原生渲染，内存服务替身不操作设备。浅色紧凑视口 688×550pt，深色宽视口 1040×800pt，分别使用 2/9 个 Profile、长名称、隐私开关和身份待确认场景。

| 展开 Profile 场景 | 2.62 内容高度 | 2.63 内容高度 | 结果 |
| --- | ---: | ---: | --- |
| 紧凑两卡 | 597pt | 540pt | 少 57pt，两张号码完整显示 |
| 紧凑九卡 | 610pt | 568pt | 少 42pt，外层仍有 18pt 滚动，列表内部可滚动 |
| 宽窗两卡 | 731pt | 626pt | 少 105pt |
| 宽窗九卡 | 823pt | 742pt | 少 81pt |

通信卡在这组 A/B 中使用同一 210pt 无操作占位。因此表格衡量读卡器区域布局，不证明真实 IMS 展开状态的全页高度。所有操作与错误仍允许滚动访问，不为指标裁切内容。详细方法、截图和文件哈希见 `build/optimization/2026-09-30-263-ui/reader-review.md`。

## 验证结果

- 生产 ReaderRuntimeStore 的 30 组、ReaderESIMStore 的 12 组定向回归通过；基线缺陷及修复日志在 `build/optimization/2026-09-30-reader-state-results/`。
- 一次综合离线门禁通过，包含 Rust 429 项、Go 定向与竞态、Swift BLE/短信/请求策略/读卡器及模拟发布回滚。原始日志为 `build/optimization/2026-09-30-263-ui/regression.log`。
- 菜单栏正常版及 NO_FAX 条件编译各完成 10 次原生渲染、8 种显示组合，并验证隐私、独立状态和导航无业务副作用。
- 传真 34 个原生渲染场景及 31 项字段/操作存在性检查通过；短信/关于自适应状态保持、调试忙碌回车、窗口生命周期和受保护图标呈现测试通过。
- 源码交叉审查确认顶部工具栏、ContentView、23 份资源文件、传真全部控件/API、代理和 NAS 相关实现未改。FaxStore 仅发布现有结果快照。共享按钮和卡片样式会改变传真视觉，不声称传真像素完全不变。
- 本机实际 USB 读卡器枚举、共享连接、事务、SELECT MF 和 USIM 身份格式读取通过。输出不包含真实号码、IMSI、ICCID、ATR 或 AKA 数据；没有执行真实切卡、下载、短信、电话或传真收发。
- 最终完整 macOS27 arm64 Release 编译成功，版本 2.63/build263；发布脚本签名校验、DMG 校验及桌面副本 SHA256 对比通过。本机 ad-hoc 签名，未公证，未使用 UPX。

## 暂缓项与重新开展条件

- 不开展全 Rust 重写、数据库/状态框架更换、无依据轮询调参或全项目缓存清理；当前收益不足以覆盖回归及重建成本。
- 同名读卡器在连接标志完全不变时换另一张 eUICC 的列表失效，是基线中已有的候选问题。取得可复现身份/会话序列后独立处理；不把现有 ICCID 显示防护写成该问题已彻底修复。
- macOS27 音频弃用与已有 Rust 诊断字段告警保留，不为消除告警扰动通话链路。
- 长稳、睡眠恢复、BLE 实际重连、多读卡器并行及运营商端到端业务没有在本轮验证。用户已确认的 9eSIM 切卡正常不等于新包已做真实切卡验收。CTExcel 呼入保持暂缓。
