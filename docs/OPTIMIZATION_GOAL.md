## 基线与测量

快照工具：`ruby scripts/capture-optimization-baseline.rb capture <新目录>`。产物只保存在已忽略、仅本人可读的本地 build 目录，不提交设备身份、真实短信、凭据或日志。

隔离回归：`sh scripts/test-optimization-isolated.sh`。包含临时 socket/本地 loopback 测试，不启动生产 App、不使用真实号卡/代理/NAS；不替代真机验收。原始测量及构建日志保存在 `build/optimization/`。

每次 A/B 必须固定版本快照、Release 配置、完整/无传真变体、架构、部署目标、工具链、网络/设备组合及数据规模。冷构建、热构建、前台与后台结果分开，记录原始样本、预热及 p50/p95，不混用不同机器/运营商条件。

## 执行顺序与停止线

1. 先验证 VoWiFi 续期/保活、BLE 连接/服务发现无回调、后端 socket 已创建但不响应三类假设，保留现有代次隔离、退避和写操作保护。只有复现缺口才修复。
2. 再测短信存储统计、日期解析与 UI 重复分组；不先建缓存、连接池或新数据库。
3. 最后看构建效率与无引用冗余；没有证据不删除历史源文件/恢复材料/用户数据。

普通性能优化的实现+验证+维护预算 ≤1 工程日；严重稳定性问题优先最小修复，预计 >2 工程日则重新评估，不自动扩大为重写。连续两轮试验未达门槛、收益处于噪声内、超过预算或关键功能退化，就停止该候选并记录原因。

立即否决条件：串 Profile、重复硬件写入、已确认数据丢失、单次丢包导致断话、重启风暴、安全/隐私退化。不得以通用 watchdog 强杀 eSIM 写入或在用通话。
